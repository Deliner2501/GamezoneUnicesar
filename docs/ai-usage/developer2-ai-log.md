\## Prompts and Responses



1\. Bro, the project structure ended up with the com.mycompany package instead of com.gamezone. How serious is this, and how do I fix it without breaking what my team already has?



That default package is generated by Maven when it is not customized when creating the project. It is the team lead's responsibility to fix it before the team starts coding their modules, to avoid reorganizing files later. I recommend moving the file and fixing the pom.xml using a separate branch and a Pull Request, without touching develop directly.



2\. I am seeing different information than I expected on GitHub. Does it matter which branch I am on, main or develop, when I clone or check the repository?



The Code button to clone on GitHub brings down the entire repository with all its branches, no matter which one is selected in the browser at that moment. What does matter is the branch you switch to after cloning, using git checkout in the terminal.



3\. A teammate is proposing to split the persistence and service class of my module into two separate classes, one for customers and one for sellers. Is that correct, or does it contradict what the workshop guide asks for?



I compared the class distribution explicitly required by the workshop, five classes per developer meaning one abstract class, two subclasses, one persistence class, and one service class, against your teammate's proposal, and found it would generate more classes than allowed, and would also be inconsistent with the pattern already used in the product module of the same project.



4\. If I create the persistence folder in my branch and another teammate creates the same folder in theirs with their own classes, will that not cause a conflict when we merge everything into develop?



Git merges files, not entire folders, so two teammates can create the same folder with different files, for example PersonDAO.java and ProductDAO.java inside persistence, without causing any conflict when merging. A conflict would only happen if two people edit the exact same file at the same time.



5\. A teammate reorganized the project structure and now the classes I had already coded ended up empty. How do I proceed without losing my progress or duplicating unnecessary work?



You will need to rewrite the content of the affected classes. I recommend doing it with individual commits per class instead of one combined commit for everything, to maintain the change traceability required by the workshop's workflow.



6\. Does my class name need to include the full package, meaning should it be written as com.gamezone.model.Person instead of just Person?



That is the difference between a class name and its fully qualified name, which includes the package. The fully qualified name is only used to locate the class from other parts of the code, for example in an import, but it is not the actual name of the class or the file.



7\. I need to document my AI usage in a file, but I do not know how to create that file correctly. Do I do it in Word and upload it like that?



That file needs to be plain text with a .md extension, not a Word document. You can create it directly from the terminal using the notepad command followed by the file name, so it is created with the correct extension from the start.



8\. I made the commit, but when I did push I got an error saying the branch has no upstream. What does that mean and how do I fix it?



That error appears the first time you push a new branch to GitHub, because there is not yet an established connection between your local branch and the remote one. Use the command the terminal itself suggests, git push --set-upstream origin branch-name, to establish that connection, which is only needed the first time.
